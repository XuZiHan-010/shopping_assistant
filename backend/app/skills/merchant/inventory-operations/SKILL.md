## 库存运营与每日简报

本店的库存以"件"为单位；每一次写操作都只是起草，**不能自批或自动应用**，
必须由商家在审批界面确认后才会真正改动库存。

### 每日简报

- 简报只用本轮授权工具在这次调用里取到的结果拼装：`get_inventory_alerts` 与待批准草稿；
  昨天的简报、历史总结、记忆都不是事实来源；
- 排序按金额大小优先，但**有硬时限的条目可以排到金额更高的条目前面**；金额未知的条目
  不自动排到末尾——用具体规则判断，不用"没有数字就靠后"这种简化；
- 正文最多 3–6 条，其余折叠成一条"另有 N 项"；
- 简报要注明数据截至时间与生成时间，商家所在时区显示；
- 一个商家一个营业日只有一份简报；商家主动要求重新生成时，是**版本替换**（版本号 +1），
  不是新增一份；
- 简报中商家/顾客信号相关内容只能引用已聚合或脱敏后的结果，**不出现顾客标识或别名**；
- 生成失败时展示安全的降级说明，旧简报不能被误标成"今天的"。

### 数字与规则

- 补货点、安全库存等规则属于商家自己配置，Skill 只能报告它们的效果，不能重新设定；
- 由工具返回的数字推算出的结论（比如还能卖几天）要连同推算依据一起说明。

### 补货与库存动作

- 用 `draft_restock` 起草补货，必须给出明确的增量数字与理由，理由要能对应到本轮工具结果里的数字
  （比如"每天卖 3 件，60 件够卖约 20 天"）；
- 补货只能起草，**不能自批、不能自动应用**：起草成功后要明确告诉商家需要去审批界面确认。

### 滞销与积压

- 告警提示滞销时，说明三种可选处置：维持不变、降价促销、下架；
- 把决定所需的数字放在一起：还剩多少、当前销售速度、临期日期（如有）、边际（如需要降价则需要定价 Skill 的数据）；
- 说明数字指向哪个方向：有明确临期日期且时间不多，倾向降价；耐存放且占用成本低，倾向维持；
  任何允许价位都卖不掉的，倾向下架；
- 库存暂停、下架属于本 Skill 的起草范围；降价促销要交给定价与促销 Skill 处理，不在本 Skill 代做。

### 交接

- 涉及降价的滞销处置，交给定价与促销 Skill，附带剩余量、临期时间与销售速度；
- 只讨论"卖得怎样"、不涉及任何库存动作的问题，交给业绩洞察 Skill。
