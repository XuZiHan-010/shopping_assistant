## 2026-09-28 双端 UI 重设计原型

双端重设计稿双击打开即可，无需后端；字体走 Google Fonts，离线时回退到系统宋体 / 黑体。刷新即重置。

**设计语言「市集大厅」**：Borough 取自伦敦 Borough Market。奶油纸面做底，铸铁绿做结构，
砖红只给助手与主操作，金色只做细线与招牌；标题用 Fraunces + 思源宋体，正文 Instrument Sans + 思源黑体。
两端共用色板与字体，商家端更紧凑，顾客端更松弛。拱门 + 字母 B 的新标只是提案，
替换 `frontend/public/borough-logo.svg` 需另行确认。

**商家端第三版（2026-09-28 定稿）**（`#home` / `#catalog` / `#orders` / `#inventory` / `#approvals` / `#after-sales` / `#signals` / `#knowledge`）：
结构对齐 Anthropic retail `merchant-web`：侧栏 + 主视图，**运营助手默认收起**，
点侧栏“运营助手”、页面上任意“问助手”或 `Ctrl/⌘ + J` 打开；对话历史在助手栏的“历史”里。
配色回到第一版「市集大厅」（铸铁绿侧栏、奶油纸面、金色细线、衬线标题）。首页自上而下：
问候 → 今日简报（浅色信笺，含“去审批”入口）→ 主指标面板（净成交额大数字 + 本周/上周趋势 + 类目归因，
订单 / 客单价 / 退款率缩成底部一行，点击即问原因）→ 需要你处理 + 助手发现/最近订单。左下角账号区打开“偏好设置”：
主题（跟随系统/浅色/深色）、语言（中文/English）、界面字号、助手快捷键，保存在本机。
（Anthropic 本地演示左下角的 Preferences 是 Next.js 开发工具，不是产品功能，没有照搬其开发者选项。）
仍保留 Borough 的长处：思考过程（工具调用）、分析来源、Reviewer 质量状态、降级提示（R7）、采纳/赞踩；
审批页按 `batch_id` 分组、可勾选批量批准，每项显示“现在 → 批准后”与护栏检查。

**商家端实施状态（2026-09-30）**：**已实施**。W 已把这一版接入 `frontend/`（外壳、助手栏、首页、订单页、商品页与其余页面换样式），
数字全部来自后端接口，原型里的示意数字没有进入页面。与原型的逐页差异（侧栏计数徽标、类目归因条形图、审批列表内联对比等）
记录在 `.superpowers/sdd/2026-09-28-merchant-workbench-redesign/task-11-report.md`。

**顾客端第二版（2026-09-28，**用户已定稿为顾客端前端模板**）**：用户决定顾客端直接对齐 Anthropic retail `storefront-web` 的结构，颜色保留 Borough。
顶栏 = 品牌 · 「智能助手 / 订单」视图切换 · 「动态」· 身份；右侧常驻购物车（窄屏收成抽屉）；主区底部常驻输入框。
首页自上而下：日期与问候 → 订单概况一句话 → 四张快捷提问卡 → 进行中的订单（每单“问问”，待付款显示“去支付”）
→ 本周热门（近 30 天销量前 8，可展开全部商品）。开始提问后主区换成对话；“动态”抽屉收拢了本轮工具过程与分析来源、
顾客记忆（可关/删）和对话记录。左下角齿轮是偏好设置（主题 / 语言 / 字号，存本机）——Anthropic 本地演示左下角的 “N”
是 Next.js 开发工具，不是产品功能。第一期对话仍是文字气泡（工具步骤可展开、降级提示内联），对话内嵌商品卡 / 对比表 /
加购确认卡属于第二期。24 个演示商品保留五个类目，换成了真实商品名；#03 缺产地、#05 说明很短、#06 无图这三个刻意缺口保留。
商品图目前是类目色块 + 线稿占位，正式图片由用户外部 AI 生成后放进 `shop/public/demo/products/`。

**实施状态（2026-09-30）**：WS 已把这一版交互接入 `shop/` 的真实 API、演示商品目录与脚本化验收。
原型里的数字仍只是示意；正式页面的订单、金额与热门排序均从后端取得。
23 张商品原图尚待用户交付，当前页面按规格显示“暂无图片”占位；图片接入见 WS 实施计划 Task 12。

## Borough 双端 Agent 原型

双击 `borough-dual-agent-prototype.html` 打开，无需依赖、后端或外部字体；刷新即重置。

- **顾客商城**：顾客 Agent 做推荐、加购、结账交接、查物流、起草退货申请（须顾客在页面确认）、记住偏好。
- **商家工作台**：商家 Agent 做每日简报、GMV 归因（结构化查询意图 → 模板 SQL）、明细导出、规则问答，
  以及商品内容、优惠券、工单回复三类暂存改动（须商家审批）。
- **双端联动**：顾客侧产生的「商品信息缺口」「退货申请」会作为脱敏信号进入商家简报；商家批准的改动
  （补全保质期、上线优惠券、同意退货）会回到顾客侧。
- **双端全景**：平台内核、数据层、从蓝图带过来的部分（原样 / 适配 / 新增 / 不引入），以及待确认的决策清单。

页面顶部虚线标签是**尚未裁定的假设**（模型、R4、融合方式、顾客身份），原型按推荐答案搭建，
不代表已定方案。商品、价格、经营数字均为示意。

# 外部 Commerce Agents 交互沙盘

双击 `commerce-agents-sandbox.html`，用浏览器打开即可。无需安装依赖或启动后端。
沿用 Claude Code 原沙盘的布局和零售流程，补充交互；原始文件和 Claude 在线 Artifact 没有被覆盖。

## 使用方式

1. 顶部选择 Anthropic 或 Shopify，再选择顾客/商家界面。
2. 左侧「场景目录」选择流程，右侧查看对话；事件页展示模拟事件。
3. 商家草稿可以批准或丢弃，修改预算可以体验护栏拦截。
4. 购物车可以增减数量、移除商品；Shopify 订单需要模拟完成结账并打开凭据和权限开关。
5. 旅行可选择日期与晚数，电信可选择套餐与线路，票务可体验保留、过期、候补与转赠。
6. 页面底部可查看覆盖说明、重置沙盘。刷新也会重置所有数据。

## 范围

这是独立的前端学习原型，不属于 Borough 生产功能，未放入 `public/` 或生产入口。
使用本地状态与预设脚本，无模型、Shopify、UCP、支付或调度服务调用，也不加载外部字体。
新增场景的数字均为示意；上游没有界面的 Shopify 商家端使用自绘界面。

事件外层字段修正了工具名、调用 ID、状态与 UI component 名；卡片 payload 仍然是缩减示意，
不能作为上游完整 API 契约。旅行、电信、票务覆盖代表流程，未宣称实现全部上游能力。
部署、MCP、提示缓存、历史压缩、评测和脚手架不做伪后端，仅标注为源码阅读方向。

Shopify 的促销与活动批准后仅记录决策，不创建实际折扣或投放广告，与固定版本的
`merchant/api/staging.py` 中 `_LEDGER_ONLY` 行为一致。
