- 日期：2026-09-28
- 状态：
  - **视觉与布局已由用户定稿**；
  - §3.5 的冲突已由用户裁定，并同步到 PRD（M1、§11.2.3、§15「W」）和契约（§8.12.4）；
  - 实施计划为 `plans/2026-09-28-merchant-workbench-redesign.md`，尚未开工。
- 定稿原型：`frontend/prototypes/borough-merchant-redesign.html`（第三版）
- 适用范围：商家端 Vue 应用 `frontend/`；顾客端 `shop/` 另行设计

## 一、裁定

2026-09-28，用户确认商家端前端**按第三版原型实施**。这一版经过三轮评审：

| 版本 | 用户反馈 | 结论 |
| --- | --- | --- |
| 第一版「市集大厅」 | 内容丰富，但首屏抓不到重点 | 保留配色，放弃布局 |
| 第二版（照搬 Anthropic `merchant-web`） | 布局对了，但配色太朴素 | 保留布局，放弃配色 |
| 第三版 | 定稿 | Anthropic 布局 + 第一版配色 |

Codex 另做的简洁版对照稿（`borough-merchant-simple.html`）已按用户要求删除，不作参考。

## 二、定稿要点

### 2.1 外壳

- 布局为侧栏、主视图、助手栏三列。**助手栏默认收起**，打开方式有三种：
  - 点侧栏的“✦ 运营助手”；
  - 点页面上任意“问助手”；
  - 按 `Ctrl/⌘ + J`。
  
  `Esc` 关闭助手栏。
- 侧栏分四组（2026-09-28 裁定后，与原型略有不同）：
  - 工作区：首页 / 商品 / 订单 / 库存；
  - 运营：待审批 / 售后 / 顾客信号 / 记忆；
  - 运营助手；
  - 管理：知识库，N5 起加运维看板。进入须管理员令牌。
- 侧栏**不放“对话记录”**。对话历史放在助手栏头部的“历史”里。
- 左下角账号区打开“偏好设置”，内容为：
  - 主题：跟随系统 / 浅色 / 深色；
  - 语言：中文 / English；
  - 界面字号；
  - 助手快捷键说明。
- 页面上不出现 PROTOTYPE 一类的备注。

### 2.2 首页（自上而下）

1. **问候**：显示日期，加一句衬线字体的问候语。
2. **今日简报**：浅色信笺卡片，金色左边线配奶油到金色的渐变。正文用黑体，关键数字用砖红加粗。“去审批（N）”入口合并在简报按钮里。
3. **主指标面板**：只突出一个指标，即净成交额。
   - 左边是大数字，加本周对上周的趋势图；
   - 右边是“变化来自哪里”的类目归因，加一句结论；
   - 底部一行是三项辅助指标，点击任一项即问助手原因。原型写的是订单、客单价、退款率；实施时改为已登记的订单量、退款金额、退货率，见 §3.3。
4. **需要你处理**：带筛选，最多显示 5 行。
5. **最近订单**：原型中的“助手发现”不实施，见 §3.3。

### 2.3 视觉 token

| 用途 | 取值 |
| --- | --- |
| 纸面 / 卡片 | `--ground #f6f1e7` / `--card #fffdf8`，另叠 SVG 细颗粒 |
| 金色（细线、选中条、商标） | `--gilt #c39a3a` |
| 砖红（助手与主操作） | `--accent #b5502f` |
| 侧栏 | 铸铁绿渐变，`--side-*` 一组 token |
| 标题字体 | Fraunces + Noto Serif SC |
| 正文字体 | Instrument Sans + 思源黑体 |
| 深色模式 | 墨绿底配金色；定义两份：`data-theme="dark"` 一份，`system` 下的 `prefers-color-scheme` 一份 |
| 字号档 | `--scale` 取 0.92 / 1 / 1.1 |

## 三、能否直接迁移

**不能整份搬过去，但视觉层几乎可以原样复用。** 原型是单文件 HTML，数据写死，交互靠手写 DOM 操作。Vue 端已有 v2 Adapter、Store、SSE 和测试体系，所以迁移分三类处理：

### 3.1 可以直接复用

- **CSS 与 token**：
  - `:root` 色板、深色两份定义、`--scale` 字号档、纸面颗粒，整体替换 `frontend/src/assets/tokens.css`；
  - 现有 `--color-*`、`--space-*` 变量名被各组件引用，**先保留旧变量名、改指向新值**，再逐步收敛。
- **各区块样式**：侧栏、简报、指标面板、表格、审批卡、助手栏的样式基本原样拆进对应组件的 `<style scoped>`。
  - 原型中 `.x span` 这类后代选择器曾波及其他元素，迁移时统一改成 class 或子选择器。
- **拱门商标 SVG**：可以直接用。替换 `frontend/public/borough-logo.svg` 仍需另行确认。
- **响应式断点**：
  - 1280px：首页改单列；
  - 1100px：助手栏改抽屉；
  - 960px：指标面板堆叠；
  - 820px：侧栏改抽屉，出现顶栏。

### 3.2 需要按原型重写（逻辑已有，只换外壳）

| 原型部分 | 现有代码 | 迁移做法 |
| --- | --- | --- |
| 侧栏 + 主视图外壳 | 无（`OpsAssistantView` 顶部有一排 RouterLink） | 新建 `MerchantShell.vue` 作为布局路由，各视图作为子路由 |
| 助手栏 | `OpsAssistantView.vue` + `stores/opsChat.ts` | 聊天区抽成 `AssistantRail.vue` 并常驻外壳。保留 SSE、工具步骤、降级、反馈和猜你想问；“问助手”继续走 `opsChat.prefill()`，只填不发 |
| 助手栏“历史” | `OpsConversationList.vue` | 移进助手栏的历史面板 |
| 商家切换 | `MerchantSwitcher.vue` | 换样式，放到侧栏品牌区 |
| 偏好设置 | `LanguageSwitcher.vue` + `stores/locale.ts` | 新建偏好面板。语言沿用 locale store；主题和字号是纯前端偏好，存 localStorage，读写包 try/catch |
| 今日简报 | `TodayView.vue` + `fetchDailyBrief` | 首页简报卡读 `DailyBrief.items`，见 §4.2 |
| 需要你处理 | 库存告警、草稿、售后、信号四个 Store | 首页聚合四个现有接口，前端合并排序 |
| 待审批 | `ApprovalListView.vue` / `ApprovalView.vue` | `DraftSummary.batchId` 已有，可以按批次分组。批量批准仍须**逐条**取批准证据再逐条 `apply`，不新增批量写接口 |
| 售后 / 顾客信号 / 库存 / 知识库 | 对应 View 均已实现 | 只换样式 |
| 商品 | `GET /api/v2/merchant/products/content` | 已有内容完整度与库存摘要，足够支撑商品页 |
| 趋势图 | 原型手写 SVG | 改用项目现有 ECharts（`useEChart`、`utils/chart.ts`），配色换成新 token |

### 3.3 原型里有、后端原本没有的部分（契约已补，2026-09-28）

| 原型部分 | 处置 |
| --- | --- |
| 首页主指标面板 | 新增 `GET /api/v2/merchant/metrics/overview`（契约 §8.12.4）。<br>- 主指标：净成交额的本期与等长基期对比、逐日趋势、类目归因（前 5 项，其余合计）；<br>- **底部三项改为已登记的受控指标**：订单量、退款金额、退货率；<br>- 原型里的“客单价”“退款率”不是已登记口径，不新造；<br>- 数字由后端确定性计算，不调用 LLM |
| 订单页、首页“最近订单” | 新增 `GET /api/v2/merchant/orders` 与 `GET /api/v2/merchant/orders/{order_id}`：只读、只含 v2 交易订单、顾客只出现脱敏别名。原型里的“物流停滞”状态不在履约模型中，不展示 |
| 助手发现 | 与简报条目重叠，没有独立数据来源，**不实施**。首页右栏只保留“最近订单” |

**不得用写死的示意数字冒充真实数据（R7）。**

### 3.4 原型没有、现有代码有的部分

- **商家记忆页**（`MerchantMemoryView.vue`，`/memories`）：原型侧栏没有这一项，迁移时放进“运营”分组。它与“管理”分组里的知识库位置不同，满足 PRD M11 的区分要求。

| 原型做法 | PRD 现行条款 | 说明 |

| 侧栏有“知识库” | M1：**知识库不进普通商家工作台**（管理员后台，Q13） | **裁定：保留**。放进侧栏“管理”分组，进入须管理员令牌，权限不变；N5 运维看板也放在这里 |
| 助手栏默认收起 | M1：助手在桌面端**常驻侧栏** | 已改 M1：所有页面可用，桌面端默认收起 |

## 四、实施时必须遵守的约束

### 4.1 路由与 PRD 同步

- 现行裁定（PRD §15，2026-09-27「选项 C」）是 `/` 为 v2 运营助手整页。本次改为：
  - `/` 为首页；
  - 助手改为常驻外壳的侧栏。
- PRD 已同步（2026-09-28）。实施时要在同一次变更中改 `router/index.ts` 注释、`router/index.spec.ts` 和相关 e2e 的入口，e2e 只改入口、不删断言。
- `/ops-assistant` 旧地址要重定向到首页，并自动打开助手栏。

### 4.2 简报文案（R7）

- 当日简报是确定性规则汇总，**界面不得写成“AI 分析”**。
- 简报卡的标题按原型写，正文逐条渲染 `items` 的 `title` 和 `evidence`，不拼一段假装模型写的话。
- `degraded` 为真时必须显示降级提示。
- “问助手原因”使用条目的 `nextActionPrompt`。

### 4.3 其他

- **字体**：原型走 Google Fonts。商家端有首屏检查（`build:first-paint`），建议自托管 woff2 子集，或设 `font-display: swap` 并保证回退字体可读。
- **双语**：原型文案全部进 `frontend/src/i18n/`，不在组件里写 `[zh, en]` 对。
- **快捷键**：`Ctrl/⌘ + J` 在 Chrome 中默认打开下载页，须 `preventDefault`。原型只在 Playwright 的 Chromium 中验证过；Firefox、Safari 和输入框聚焦时的行为，迁移时要补测。
