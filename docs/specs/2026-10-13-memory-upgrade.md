# 双端记忆升级设计

日期：2026-10-13。用户已批准实施此前讨论的升级；真实模型验收不在本次授权内。

## 行为

- 长期记忆只保存明确表达或确认的稳定偏好；含「这次、今天、送人」等任务限定的分句不沉淀。明确的长期表达可独立保存，不能靠截短证据去掉任务限定。模型可标记 `scope=LONG_TERM|SESSION`，后端仍复检原话。
- 新抽取使用按角色维护的类别/键白名单与中英别名，未知键保守拒绝。顾客保存选购/使用偏好；商家只保存回答呈现偏好。旧记录继续可见，不猜测合并。
- 商家新增可空规范键；新抽取同类同键替换当前事实并保留最新来源，相关总结立即失效并确定性重建。
- outbox 新增递增来源序号和主体记忆版本。入队在主体锁下捕获版本；写入按（用户消息时间，来源序号）比较，先比较时间，同时间再比较序号，防止较早请求晚落库后覆盖新事实。最后确认时间使用用户消息时间，重试不续期。
- 顾客删除或开关改变、商家删除事实时递增主体版本。此前版本的任务完成时直接标 DONE、不写入；这是保守的主体级屏障，删除一条也会取消同主体此前尚未写入的任务。之后新回合允许重新沉淀。
- Chat 自动注入有数量/字符上限的有效类别目录和最近少量事实；目录不含未加载正文。工具按类别读取正文，带确认时间，排除本回合已注入或经工具读取的记录；整体限制长度，超限只舍弃完整条目并标记截断。商家总结仅在已有记忆面板展示，不与事实重复注入。
- 商家新候选除规范键外还须满足对应呈现值锚点；规则、订单状态、受控写操作不能借呈现键写入。该校验是保守有限规则，真实模型精度仍须专项评测。
- 不新增独立模型选择调用；抽取仍使用现有单次调用、独立预算与每日预算守卫。记忆仍不提供业务数字/规则，不升级到知识库。

## 兼容与迁移

公共记忆 API 路径及响应字段不变，内部模型/工具载荷升级。新增字段默认兼容旧调用；旧任务版本为 0，迁移后根据旧任务时间排序分配序号。旧商家事实的规范键留空，后续只对已规范的新事实进行替换。升降级只操作本版自有表；部署迁移必须在 Web/Cron 发布前单独执行。

## 验证

每项新增行为先观察失败测试再实现。单测用 Fake LLM；事务、顺序、删除/关闭屏障、迁移和双端契约用独占可丢弃 pgvector PostgreSQL。真实模型抽取准确率、召回收益待 R3 单独授权，Fake 通过不能表述为真实模型质量通过。
