# N4 E5 上下文压缩评测（Fake LLM，2026-09-30）

> 结论：**两种策略的锚点与结构都成立。** 同日已完成真实模型对比，选型结论见 `n4-e5-compaction-real.md`（维持 `TOOL_RESULT_PRUNING`）。
> 本报告只验证结构，不代表真实模型下的摘要质量或回答质量。

## 评测集与方法

- 评测集：`backend/app/eval/datasets/compaction/n4_e5_compaction.yaml`，30 条长对话（商家 18、顾客 12，
  其中英文 4 条）。每条至少 4 个工具轮，压缩前上下文平均 15,270、最大 20,158（字符估算），全部超过
  `COMPACTION_TRIGGER_TOKENS` 默认 8,000；最后的问题依赖被压缩的早期轮次（指标值、截至时间、定义版本、草稿编号与版本）。
- 顾客历史里刻意混入提示注入与谈价话术；被压缩的轮次里埋了身份陷阱字段（`merchant_id` / `buyer_key`）。
- 评估器：`backend/app/eval/compaction_e5.py`（`uv run python -m app.eval.compaction_e5`），校验：
  `backend/tests/eval/test_n4_compaction_e5_fake.py`。
- 摘要策略使用「什么都没保留」的 Fake 摘要：锚点若仍在，只能是回填的功劳。

## 结果

| 指标 | TOOL_RESULT_PRUNING | SUMMARIZATION |
| --- | --- | --- |
| 身份保持率（压缩后提示词无身份原值） | 30/30 | 30/30 |
| 来源保持率（工具名#调用 ID、单值、截至时间、定义版本） | 30/30 | 30/30 |
| 草稿版本保持率（依赖草稿的 12 条） | 12/12 | 12/12 |
| 安全约束保持率（系统禁止项逐字保留、注入与摘要在围栏内、工具消息结构合法） | 30/30 | 30/30 |
| 诊断：历史用户原话仍可见 | 100% | 0% |
| 压缩后 / 压缩前上下文（均值） | 0.57 | 0.54 |
| 额外 LLM 调用 | 0 | 30（每条 1 次） |

评估器的有效性用变异检查确认：清理不回填锚点、锚点带出身份字段、摘要不加围栏、草稿版本不抽取，
四种改动都会让本评测变红。

## 选型

在没有真实模型证据时选 `TOOL_RESULT_PRUNING`：零 LLM 调用、行为完全确定、不吸收历史文字。
摘要策略的上下文只再短 3 个百分点，却多一次计费调用；而且它把历史里用户明确说过的约束（如「不做低于 8 折的券」）
交给摘要模型转述，摘要一旦遗漏就再也看不到——Fake 最坏情况下这一项为 0%，这个风险只有真实模型评测才能量化。

`SUMMARIZATION` 保留在 `app/agent/loop/compaction/`，可由 `COMPACTION_STRATEGY` 切换，并由本评测与单测做回归对照。

## 真实模型对比（R3，已于同日执行，见 `n4-e5-compaction-real.md`）

需要用户另行授权，申请内容：

- 接口：DeepSeek OpenAI 兼容接口，经 Borough `LlmCostGuard`；
- 模型：`deepseek-flash`；
- 次数：30 条 ×（摘要 1 次 + 两种策略压缩后各作答 1 次）= **90 次**，不用 LLM 裁判（按锚点值确定性判分）；

- 评测只用本地可丢弃 `_test` 数据库，不写生产数据。
