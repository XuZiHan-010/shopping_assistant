# F1 视觉基础与主布局设计

## 目标

为 Borough 商家 AI 助手交付可访问、响应式的三栏视觉骨架。F1 只提供正式品牌、页面布局、商家身份的视觉切换和空状态；不接入聊天 API、SSE、附件、真实 LLM 或业务数据。

## 页面与组件

`AssistantView.vue` 负责组合顶栏与三栏工作区。顶部使用单个 `MerchantSwitcher.vue` 实例：大于 560px 时位于右侧操作区，560px 及以下通过父级布局移至品牌标题下方副行。商家组件只接受显示名列表并发出选择事件，绝不保存或展示 Token、`merchant_id`。

`ConversationColumn.vue` 负责中列的消息流/空状态和输入区整体布局；它组合独立的 `ChatComposer.vue`。Composer 仅负责文本框、发送控件及附件区占位的视觉与可访问性，F1 不实现发送、上传或拖拽行为。左右侧栏只呈现后续指标/建议出现前的空状态。

`stores/chat.ts` 保持最小：`isEmptyConversation` 与 `reset()`。商家切换和新会话都会调用该动作；F2 才在此基础扩展 Mock 会话状态。F1 的商家列表是硬编码的演示显示名，并在源码中说明 F2 将由 Auth Store 替换。

## 样式与响应式

全局值拆为 `tokens.css`（颜色、字号、间距、圆角、阴影）和 `base.css`（reset、背景、焦点、减少动画）；`styles.css` 是唯一入口。视觉参照 Prototype 的轻量蓝绿色背景、浅色卡片、低强度阴影和 9–18px 圆角，但所有变量及资源使用 Borough 命名。

桌面工作区为两侧 230–280px、中列最大 760px 的三栏，页面最大宽约 1500px。1240px 右栏下置，860px 单列，560px 使用既有紧凑规则。561–580px 不添加断点；通过可收缩品牌区域、单行省略与不可换行的操作区避免溢出。

## 验证策略

不使用自建截图快照。Playwright 断言 1440px 的栏宽和结构、561/580px 顶栏不溢出、390px 输入可见、360px 无页面横向滚动，以及减少动画生效。1440×1000 与 Prototype 的视觉还原由一次人工核对完成，结论写入进度快照。

## 边界

组件不得读取 `api/generated.ts`、不得做字段转换或拼接 API URL；不建登录页，不传 `merchant_id`，不接真实接口。新建 Borough logo，不复制 `yshopping-logo.svg`；两个参考目录保持只读。
