## 一、入口与准备

- **对外只给一个链接：商家端。** 顾客端的场景一律从商家端侧栏底部的「顾客视角」进入，它在新标签页打开当前商家自己的店铺页。
  这只是一个链接：不带会话、Token 或任何参数，顾客端另起自己的访客会话，两端会话不可互换。
- 商家端打开即是首页 `/`，默认选中演示商家；运营助手在右侧助手栏，`Ctrl / ⌘ + J` 或侧栏「运营助手」打开。
- 顾客端 `/{shop_slug}` 是智能助手首页：上方六条快捷提问，中间进行中的订单与热门商品，右侧常驻购物车。
  需要订单、售后、记忆的场景，先在右上角身份菜单里「绑定演示顾客」。
- 数据是确定性演示数据：180 天经营历史由每日滚动任务维护，S1–S4 的场景数据由 `seed_demo_scenarios` 灌入
  （`docs/deployment.md`「演示前数据检查清单」）。
- **模型**：S1、S2、S5、S6、S7 的对话部分依赖已配置的模型。未配置 Key 时助手给出可见的降级说明，不会编造回答；
  这时仍可演示全部界面动作（加购、下单、支付、审批、售后、看板）与 S3、S4、S8。配置真实 Key 需要生产变更与费用两项授权。

## 二、演示边界（开场先讲）

| 边界 | 说明 |
| --- | --- |
| 身份 | 演示商家与演示顾客都不是真实登录；演示 Token 只能访问演示数据 |
| 支付与退款 | 模拟支付、模拟退款，不接任何支付渠道；退款金额由后端按订单价格快照计算 |
| 数据 | 三家固定演示商家的确定性数据；页面上的数字都来自数据库，不是模型生成 |
| 模型 | 只用 DeepSeek `deepseek-flash`；有单请求上限与全局 / 角色 / 店铺三级每日预算，耗尽即可见降级 |
| 不在本版 | 附件与 OCR、真实用户体系、多规格商品、跨店比价、顾客侧 MCP、MCP 写工具 |

## 三、场景

每条场景三栏：做什么、看什么、**这里体现的规则**。最后一栏是演示的重点——把工程约束讲出来。

### S1 售前咨询成单（顾客端）

| 步骤 | 看什么 | 体现的规则 |
| --- | --- | --- |
| 商家端点「顾客视角」 | 新标签页地址只有顾客端域名与店铺标识 | 单入口只是链接，凭证不外传；顾客端自己创建访客会话 |
| 点快捷提问「想找一双通勤穿的鞋，预算 500 元以内」 | 助手检索本店商品并给出候选，展开「查了 N 步」能看到工具调用 | 价格与库存档位只来自工具结果；只展示「有货 / 紧张 / 售罄」档位，不暴露库存数量 |
| 让助手把其中一件加入购物车 | 右侧购物车出现该商品 | 助手只能调整购物车数量；只能操作本轮对话里出现过的本店商品 |
| 绑定演示顾客 → 提交订单 | 跳到订单页，状态「待付款」 | 下单、支付、取消是界面动作，模型的工具面里没有这些能力；提交订单时占用库存，并发下单不超卖 |
| 点「去支付」 | 订单变为「已支付」，事件里出现支付记录 | 支付与 30 分钟超时关闭并发时只有一方生效；重复点击没有二次副作用 |

### S2 信息缺口闭环（顾客端 → 商家端 → 顾客端）

| 步骤 | 看什么 | 体现的规则 |
| --- | --- | --- |
| 顾客问一件商品没有填写的属性（例如某件商品的产地） | 助手说明商家没有提供，不猜测 | 缺失就是缺失：工具返回「缺失」，模型不得替商家编造 |
| 回到商家端「顾客信号」 | 出现一条内容缺口信号，只显示脱敏的顾客别名 | 商家只能看到店铺级脱敏别名，看不到顾客标识 |
| 在助手栏让助手起草补充内容 → 「待审批」里打开草稿 → 批准 | 草稿显示改动前后；批准后商品内容更新 | 商家端所有写操作都走草稿审批；批准绑定草稿版本，聊天里的「批准」不生效 |
| 回顾客端再问同一问题 | 助手给出刚补充的属性 | 顾客端读到的是批准之后的事实 |

### S3 库存告警闭环（商家端）

| 步骤 | 看什么 | 体现的规则 |
| --- | --- | --- |
| 首页「今日简报」与「需要你处理」 | 低库存告警与待批准的补货草稿 | 简报是后端规则汇总，不是模型分析；来源标注为数据库 |
| 「库存」页查看告警 | 可售量、阈值与告警行 | 库存有账本，可由事件重算出当前在库与占用 |
| 「待审批」打开补货草稿 → 批准 | 应用成功，库存增加；顾客端该商品档位恢复 | 应用时按**当前**库存复检，不按起草时的快照；重复批准没有二次副作用 |

### S4 售后闭环（顾客端 → 商家端）

| 步骤 | 看什么 | 体现的规则 |
| --- | --- | --- |
| 演示顾客在订单页对已签收订单申请退货 | 先出现确认摘要，确认后才提交 | 能否售后由后端按签收时间与规则判定；必须在界面确认，聊天里的确认不生效 |
| 商家端「售后」出现待处理工单 → 同意 | 状态推进到等待寄回 | 商家的售后决定同样走草稿审批；金额不由商家或模型指定 |
| 顾客登记寄回 → 商家登记收货并给出验货结论 | 退款记录生成 | 退款记录只在收货之后产生；库存只在验货判定可售时回补 |

### S5 业绩归因（商家端助手）

| 步骤 | 看什么 | 体现的规则 |
| --- | --- | --- |
| 问「为什么本周销售额下滑」 | 分项贡献、数据截至时间、趋势图 | 数字、公式、对比周期与图表数据点全部由后端确定性代码产生；模型只负责措辞，证据不足时用分级表述 |
| 看回答下方的来源与质量标记 | 来源为数据库；质量状态与重试次数 | 回答里的每个数字都能追溯到工具结果，追溯不到就降级 |

### S6 促销决策（商家端 → 顾客端）

| 步骤 | 看什么 | 体现的规则 |
| --- | --- | --- |
| 让助手为滞销商品起草一张折扣券 | 生成优惠券草稿 | 起草时就按护栏校验最大优惠幅度（20% 上限），超出直接拒绝 |
| 「待审批」批准草稿 | 券状态变为已生效 | 批准时按当前护栏再校验一次 |
| 顾客视角查看店铺 | 顾客端显示已生效的券 | 顾客端助手只告知已生效的券，不谈价、不承诺规则之外的优惠 |

### S7 口径问答（商家端助手）

| 步骤 | 看什么 | 体现的规则 |
| --- | --- | --- |
| 问「净成交额怎么算」 | 带引用的回答，声明定义版本 | 口径只来自受控的指标资产与知识库；SQL 口径供人核对，不会回流成待执行的 SQL |
| 「管理 → 知识库」输入管理员令牌 | 知识目录与索引状态（混合检索 / 仅关键词） | 管理员令牌走独立请求头，不与商家会话混用；检索降级会在回答来源上标出 |

### S8 外部只读接入（MCP）

| 步骤 | 看什么 | 体现的规则 |
| --- | --- | --- |
| 命令行签发一张 24 小时的只读凭证 | 凭证原值只显示这一次 | 凭证只经后端命令行签发与撤销，没有任何 HTTP 管理路径；库里只存指纹 |
| 用标准 MCP 客户端连接 `POST /api/v2/merchant/mcp` 并调用指标工具 | 数值、截至时间、定义版本与工作台一致 | 商家范围只从凭证解析；只有只读工具，写工具与审批证据不可见；鉴权先于读取请求正文 |
| 命令行撤销该凭证，再调用一次 | 立即 401 | 撤销即时生效，校验结果不缓存 |

### 收尾：运维看板（商家端「管理 → 运维看板」）

输入管理员令牌后展示三级预算余量、当日成本、限流与降级计数、工具错误率、路由 p95 与 Chat BI 概览。页面只读。
讲两点：顾客端是公开流量，角色级预算保证它耗尽时商家工作台不受影响；成本按调用当时的价格版本记账，价格变动不回算历史。

## 四、已知的演示限制

- 顾客可见的平台规则文档目前只有骨架，只有「退货业务流程」有实质内容；规则问答请用快捷提问里那一条（退货退款流程）。
- 快捷提问是固定文案，回答照常走工具循环与闸门，没有预置答案；模型的实际表现以当场为准。
- 访客（未绑定演示顾客）问订单、售后或让助手记住偏好时，助手会引导先绑定身份——这是设计，不是故障。
- 运维看板里的限流、降级、工具与耗时指标是进程内近似值，重启即清零。
