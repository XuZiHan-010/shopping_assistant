# Backend B0+B1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立可启动、可测试、可容器化的 FastAPI 后端，并完成 PostgreSQL 基础迁移、演示 Token 认证、可信商家上下文、会话仓储隔离和越权审计。

**Architecture:** `app.main.create_app()` 负责装配 HTTP 层，配置、日志和错误处理集中在 `app.core`。数据库通过 SQLAlchemy Async Session 注入，Alembic 管理默认 `public` schema；Bearer Token 只在服务端解析为 `MerchantContext`，Repository 的每个商家资源方法都显式接收 `merchant_id`，跨商家探测通过独立的授权服务返回 `403` 并写 `audit_logs`。

**Tech Stack:** Python 3.12、FastAPI、Pydantic v2、pydantic-settings、SQLAlchemy 2、Alembic、psycopg 3、structlog、pytest、pytest-asyncio、httpx、Ruff、mypy、PostgreSQL 16、Docker。

## Global Constraints

- 面向用户的响应、错误信息和项目文档使用中文；代码标识符使用英文。
- 不调用真实 LLM，不读取或使用 `LLM_API_KEY`，所有测试零模型费用。
- 不创建 `users` 表、JWT、登录接口、经营数据表、Chat API、附件或 P1 能力。
- Python 发行项目名为 `borough-merchant-ai`，导入根包固定为 `app`。
- PostgreSQL 使用默认 `public` schema，不设置 `search_path` 或 `version_table_schema`。
- 商家身份只来自服务端演示 Token 映射，不接受客户端传入的 `merchant_id`。
- 所有资源查询显式注入 `merchant_id`；跨商家访问返回 `403` 并记录安全审计。
- `/api/health` 不查数据库、不调用 LLM；`/api/ready` 只执行轻量数据库探针。
- 自动化测试不得用 SQLite 代替 PostgreSQL。
- 未经用户明确许可，不执行 `git commit`、`git push` 或 Railway 部署。

```python
    database_url: str
```

Dockerfile 使用 Python 3.12 slim，依赖层按锁文件缓存，运行用户为 `app`。启动命令使用 exec form 调用一个读取 `PORT` 的 Python 启动模块，避免 shell form：

```dockerfile
CMD ["python", "-m", "app.run"]
```

`app.run` 调用 Uvicorn，host 固定 `0.0.0.0`，port 读取 `PORT`。Compose 只提供本地 Backend 与 PostgreSQL，不包含 Redis、Worker、MySQL 或 Doris。

- [ ] **Step 2: 以容器行为验证构建、非 root 用户和启动命令**

Run:

```powershell
docker build -t borough-merchant-ai-b0-b1 .
docker image inspect borough-merchant-ai-b0-b1
docker run --rm --entrypoint python borough-merchant-ai-b0-b1 -c "import os; print(os.getuid())"
```

Expected: 构建成功；镜像配置的 `User` 为 `app`；容器内 UID 不是 `0`；镜像 `Cmd` 为 `["python","-m","app.run"]`。

- [ ] **Step 3: 同步项目索引**

把本轮创建的 `backend/`、`.env.example`、`.gitignore` 和 `docker-compose.yml` 从规划状态同步为现有状态；不得改动参考项目目录。

Run:

```powershell
uv sync

uv run mypy app

docker compose config
docker build -t borough-merchant-ai-b0-b1 .
```

- [ ] **Step 5: 验证服务行为**

启动本地 PostgreSQL 和 Backend 后验证：

```text
GET /api/health                → 200，不依赖数据库业务查询
GET /api/ready                 → 200，数据库不可用时 503 安全错误
GET /api/demo/merchants        → 开启时 200，关闭或 production 时 404
任意受保护依赖缺少 Token       → 401 AUTH_REQUIRED
跨商家资源访问                 → 403 MERCHANT_SCOPE_VIOLATION + audit_logs
```

不得调用 `/api/chat`、OCR、日报或任何真实模型接口。
